# План Grizzly Notes

Требования: ТЗ «Grizzly Personal RU» v1.0 от 06.11.2026. Название для пользователя — **Grizzly Notes**, как на макетах.

Согласованное отклонение от ТЗ (заказчик, 06.11.2026): ТЗ называет Apple Silicon первой платформой приёмки, но разработка идёт на Intel, поэтому приёмка двухшаговая. Версия 1.0 считается готовой только после Этапа 2.

## Этап 1. Разработка на Intel

| Этап | Результат | Критерий выхода |
|---|---|---|
| M0 Аудит | Git, базовые сборки и тесты, быстрый набор тестов | Сборка x86_64 работает; для arm64 есть результат или точный блокер |
| M1 Изоляция | Отдельные идентификатор, данные, отключённые обновления, оболочка по макетам | Установленный Grizzly и его данные не затронуты |
| M2 Основа | SQLite, миграции, страницы, автосохранение, резервная копия | Первый вертикальный сценарий проходит автоматически |
| M3 Прототип редактора | Абзац, заголовок, задача | Проверены выделение через блоки, курсор, Undo, Unicode |
| M4 База знаний | Все типы блоков, дерево, ссылки, поиск, корзина | Работа без файловых диалогов |
| M5 Базы | Свойства, таблица, фильтры, карточка записи | Запись открывается как страница; даты не сдвигаются |
| M6 Представления | Доска, список, календарь, галерея, шаблоны | Одна запись согласована во всех видах |
| M7 Перенос данных | Импорт, экспорт, история, локализация | Проверка на фикстурах, оригиналы не меняются |
| M8-Intel Сборка | AT-01–AT-16, сборка x86_64, нагрузочный прогон | Отчёт, контрольная сумма, демо-пространство |

## Этап 2. Перенос на Apple Silicon

Нужен Mac на Apple Silicon, желательно 16 ГБ и новая macOS.

1. Нативная сборка и тесты, исправление ошибок нового компилятора.
2. Универсальная сборка (`lipo`) и подпись.
3. Перенос архива Intel → Apple Silicon и обратно.
4. Проверка и отключение Writing Tools.
5. Ручной прогон редактора, раскладок, VoiceOver, тем на новой macOS.
6. AT-17 на контрольном устройстве.
7. Выпуск 1.0.

M9 (P3: связи, агрегаты, формулы) — после 1.0, отдельным решением.

## Правила на каждом этапе

- Код не зависит от архитектуры; сборка под arm64 проверяется компиляцией на границах этапов.
- Результат фиксируется в `STATUS.md`, проверки — в `TEST_REPORT.md`.
- Работа останавливается при 70% использования 5-часового лимита; недельный лимит причиной остановки не является.
