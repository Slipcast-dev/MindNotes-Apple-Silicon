# Сборка, запуск и восстановление

Нужны Mac на Apple Silicon, macOS 26 или новее и Command Line Tools (`xcode-select --install`). Для JS-тестов нужен Node.js. Сборка для Intel не поддерживается (ADR-0009).

## Сборка

```bash
./scripts/build-app.sh
```

Результат: `build/Minerva Noema.app`, arm64, подпись ad-hoc (это не notarization). Отладочная сборка в другой каталог:

```bash
SWIFT_OPT=-Onone OUT=build/debug ./scripts/build-app.sh
```

Установленный Grizzly не заменяется: у этой сборки другое имя, идентификатор и каталог данных (`~/Library/Application Support/MinervaNoema`).

## Проверочный запуск

Копия с идентификатором `local.personal.MinervaNoema.test` получает свои настройки и свой каталог данных, настоящие данные не затрагиваются. Пространство для неё выбирайте только во временной папке.

```bash
./scripts/run-isolated.sh
```

Завершить копию и удалить всё, что она создала, кроме выбранного пространства:

```bash
./scripts/run-isolated.sh clean
```

## Тесты

```bash
./scripts/test.sh
```

Быстрый набор рабочего пространства без UI:

```bash
./scripts/test-notes.sh
```

Границы слоёв:

```bash
./scripts/check-layers.sh
```

Thread Sanitizer:

```bash
NOTES_OPT=-sanitize=thread ./scripts/test-notes.sh
```

Замеры на данных AT-17. Первый запуск создаёт пространство в указанной папке, она должна быть временной. Замер имеет смысл только с оптимизацией: обычный `test-notes.sh` собирает без неё.

```bash
NOTES_OPT="-O" ./scripts/test-notes.sh --bench-large /tmp/minerva-large
```

## Пространство

При первом запуске создайте пространство в пустой папке на локальном диске. Не размещайте активное пространство в папках облачной синхронизации: это не поддерживается. Для переноса используйте архив.

Папка содержит `workspace.sqlite`, каталог `assets/` и служебные файлы. Копировать только `workspace.sqlite` нельзя: часть данных может находиться в журнале WAL.

## Резервная копия и восстановление

«Резервные копии» → «Создать копию» сохраняет архив в `~/Library/Application Support/MinervaNoema/Backups/`. «Сохранить копию как…» позволяет выбрать другое место. Копия на том же диске не защищает от его отказа, поэтому храните её и на другом носителе.

«Восстановить из архива…» создаёт новое пространство в новой пустой папке и сначала проверяет контрольные суммы и целостность. Текущее пространство не меняется.

Архив `.minervabackup` — обычный tar; его содержимое можно посмотреть командой `tar -tf`.

## Файлы на диске

Раздел «Файлы» показывает текстовый файл без изменений и импортирует его как новую страницу (Markdown: заголовки, списки, задачи, цитаты, код, разделители). Сам файл не меняется.

## Редактор

Меню блоков: `/` в начале строки или после пробела. Сокращения: `# `, `## `, `### `, `- `, `1. `, `[] `, `> `, `---`. Форматирование: ⌘B, ⌘I, ⌘U, ⇧⌘X, ⌘E, ⇧⌘K; те же действия в меню «Формат», по правому клику и на панели при выделении. Tab и Shift+Tab меняют вложенность.

## Импорт и экспорт

«Импорт» в боковой панели принимает файл Markdown, CSV, папку или архив экспорта Notion (`.zip`). CSV открывается с предпросмотром: кодировка, разделитель, строка заголовков, тип каждого столбца. Папка и архив импортируются под новую страницу «Импорт — …» с отчётом в начале; чтобы отменить импорт, отправьте её в корзину. Оригиналы не меняются.

Экспорт: страница — «…» → «Экспорт в Markdown…», база — «Экспорт в CSV…», всё пространство — «Настройки» → «Экспорт». Экспорт не заменяет резервную копию: история, представления и корзина в него не входят.
