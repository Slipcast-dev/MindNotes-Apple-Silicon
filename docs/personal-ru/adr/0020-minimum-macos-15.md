# ADR-0020. Минимум macOS 15

Статус: принято 13.11.2026 по решению заказчика. Заменяет в ADR-0009 только минимальную систему (26). Часть ADR-0009 про архитектуру остаётся: только arm64, Intel не поддерживается.

## Контекст

На любой Mac с Apple Silicon ставится macOS 26, поэтому ниже 26 остаются только те, кто не обновил систему. Проверка компилятором (`swiftc -typecheck -wmo -continue-building-after-errors`) показала, сколько стоит каждый минимум:

| Минимум | Что мешает |
|---|---|
| macOS 15 | 3 вызова `sharedBackgroundVisibility` в `RootView.swift` |
| macOS 14 | + прокрутка таймлайна, `Color.mix`, Writing Tools, около 10 мест |
| macOS 13 | около 85 мест: Observation, новая форма `onChange`, полный доступ EventKit и всё выше |

Поддержка 15 почти ничего не стоит, ниже 15 уже нужна заметная переделка и постоянная проверка двух вариантов кода. План перехода — `MACOS15_PLAN.md`.

## Решение

- Минимальная система — macOS 15 Sequoia: `MIN_MACOS=15.0` в `scripts/target.sh`, `.macOS(.v15)` в `Package.swift`. Web Clipper уже поддерживает 15 (ADR-0019, п. 11).
- Сборка по-прежнему на SDK 26 и новее. Возможности новее 15 используются только после `#available`. Пример — `hidingSharedBackground()`: на macOS 26+ прячет подложку Liquid Glass, на 15 ничего не делает.
- Обновление (ADR-0014) читает `LSMinimumSystemVersion` из `Info.plist` в скачанном образе и не ставит сборку, если она требует более новую систему (`SystemRequirement`). Старая программа остаётся рабочей, пользователь видит, какая система нужна.
- CI: задача `tests` на `macos-26` собирает приложение и тесты и проверяет запуск. Задача `minimum-macos` на `macos-15` запускает те же собранные тесты и готовое приложение (`scripts/smoke-launch.sh`). Собирать на `macos-15` нельзя: там SDK 15.
- macOS 13–14 не поддерживаются.

## Последствия

- На macOS 15 нет Liquid Glass: панель инструментов и стандартные элементы выглядят по-старому. Отличия в поведении SwiftUI и AppKit компилятор не ловит. Их проверяют вручную в виртуальной машине (шаг 6 плана) и тестами в CI.
- Любой новый API из SDK 26+ нужно оборачивать в `#available`, иначе сломается сборка в CI. Проверку типов с целью 15 запускает сама `build-app.sh`.
- Формат данных не меняется (схема v10). Пространства и резервные копии одинаковы на 15 и 26+.
- Чтобы снова поднять минимум, нужно поменять `scripts/target.sh`, `Package.swift` и образ задачи `minimum-macos`. Пользователи на старой системе получат отказ при обновлении, а не программу, которая не запускается.
- Если образ `macos-15` уберут из GitHub Actions, задачу `minimum-macos` придётся снять или перенести на свою машину.
