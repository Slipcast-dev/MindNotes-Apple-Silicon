# План M9: связи, свёртки, формулы

План от 10.11.2026, решения заказчика приняты. M9.1–M9.3 выполнены 11.11.2026, см. `STATUS.md`. Требования: ТЗ FR-13 (P3), приёмка AT-18 и дополнительные тесты формул (критерий готовности P3 в ТЗ). Отправная точка: выпуск 1.0.0, схема v5.

## Цель

Базы перестают быть изолированными таблицами:

- **Связь** — запись одной базы ссылается на записи другой (или той же) базы; у связанной базы видна обратная связь.
- **Свёртка** — значение из связанных записей с агрегатом: количество, сумма, среднее, минимум, максимум и др.
- **Формула** — вычисляемое свойство на ограниченном типизированном языке: числа, строки, логика, даты.

Всё работает в фильтрах, сортировке, группировке (где применимо), на всех пяти видах, во встроенных представлениях, экспорте и резервных копиях.

## Главное архитектурное решение: вычисленные значения хранятся

Фильтры и сортировка сейчас компилируются в SQL (`SQLiteWorkspace+Databases.swift`, `compile`/`order`), записи грузятся страницами по 100. Чтобы свёртку или формулу можно было фильтровать и сортировать на 20 тысячах записей, её значение **материализуется** в `property_values` в колонку своего типа результата (`value_num`, `value_text`, `value_date`/`value_ts`). Существующие индексы и компилятор фильтров работают без изменений.

Следствия:

- Пересчёт идёт **по графу зависимостей** при записи значения, а не при показе (это и требует FR-13).
- Значение может быть «грязным» (ещё не пересчитано) — для него есть флаг, видимый в UI, и досчёт при открытии пространства.
- Вычисляемые ячейки только для чтения.

Альтернатива — считать на лету в Swift и фильтровать в памяти — отвергнута: ломает постраничную загрузку и замеры AT-17.

## Схема v6 и v7

Сделано: схема v6 содержит только `config_json` и `relation_links`. M9.2 обошёлся без новой схемы: зависимости свёрток читаются из их настроек, пересчёт идёт в транзакции правки и укладывается в миллисекунды (замер в `TEST_REPORT.md`), поэтому `calc_dirty` и фоновый пересчёт не понадобились. `calc_error` и граф зависимостей формул появятся в M9.4. Ниже — исходный общий вид.

```sql
-- Настройки свойства: цель связи, параметры свёртки, текст и тип формулы.
ALTER TABLE property_definitions ADD COLUMN config_json TEXT;

-- Связь хранится одной строкой; обратное свойство читает её с другой стороны.
CREATE TABLE relation_links (
    from_page   TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    property_id TEXT NOT NULL REFERENCES property_definitions(id) ON DELETE CASCADE,
    to_page     TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
    sort_key    TEXT NOT NULL,
    PRIMARY KEY(from_page, property_id, to_page)
) WITHOUT ROWID;
CREATE INDEX relation_links_to ON relation_links(to_page, property_id);

-- Граф зависимостей на уровне свойств: формула/свёртка → от чего зависит.
CREATE TABLE property_deps (
    property_id   TEXT NOT NULL REFERENCES property_definitions(id) ON DELETE CASCADE,
    depends_on    TEXT NOT NULL REFERENCES property_definitions(id) ON DELETE CASCADE,
    via_relation  TEXT REFERENCES property_definitions(id) ON DELETE CASCADE,
    PRIMARY KEY(property_id, depends_on, via_relation)
);
CREATE INDEX property_deps_rev ON property_deps(depends_on);

-- Состояние вычисления ячейки.
ALTER TABLE property_values ADD COLUMN calc_error TEXT;   -- код ошибки формулы, NULL если значение есть
ALTER TABLE property_values ADD COLUMN calc_dirty INTEGER NOT NULL DEFAULT 0;
CREATE INDEX property_values_dirty ON property_values(property_id) WHERE calc_dirty = 1;
```

- Новые типы: `relation`, `rollup`, `formula` (`PropertyType` — строка, старые версии сохраняют неизвестный тип без потерь).
- Миграция только добавляет: существующие данные не трогаются. Перед ней — обычный снимок (`beforeMigration`).
- Сборка 1.0 откажется открывать v6 (AT-16 уже это проверяет) — это нужно сказать в заметках к выпуску.

## 1. Связи

**Модель.** `config_json`: `{ "target": <database_id>, "pair": <property_id|null> }`. По умолчанию связь **двусторонняя**: при создании в целевой базе появляется парное свойство «обратная связь» с тем же набором строк `relation_links`, прочитанным через `to_page`. Связь базы с самой собой допустима (иерархия задач).

**Правила.**

- Запись связывает только записи целевой базы; страница вне базы — нельзя.
- Предел — 1000 связей в одной ячейке (защита от случайной массовой вставки), предупреждение заранее.
- Корзина: связи на записи из корзины скрываются, но не удаляются; восстановление возвращает их. Окончательное удаление — каскад.
- Дублирование и шаблоны (FR-12): связи внутри копируемого поддерева переназначаются, внешние сохраняются. Код в `duplicateDatabaseData` и `instantiate`.
- Удаление свойства-связи удаляет пару только с подтверждением; зависящие свёртки и формулы получают ошибку «связь удалена» (AT-18), а не падают.
- Смена типа с/на связь в M9.1 не сделана (см. `KNOWN_LIMITATIONS.md`).

**Фильтры.** «содержит запись» (по части заголовка), «не содержит», «пусто», «не пусто» — через `EXISTS` по `relation_links`. Сортировка по связи — по количеству. Группировка — нет (как в FR-11 для мультивыбора не обещано).

**UI.** Ячейка — плашки с заголовками; выбор через окно с поиском по заголовку в целевой базе. Карточка записи: связи кликабельны; обратная связь видна своим свойством в карточке. Создание записи из окна выбора отложено.

## 2. Свёртки

**Модель.** `config_json`: `{ "relation": <property_id>, "target": <property_id>, "aggregate": "...", "dateMode": ... }`.

Агрегаты: `count` (записей), `count_values`, `count_unique`, `count_empty`, `percent_empty`, `sum`, `average`, `median`, `min`, `max`, `range`, `earliest`, `latest`, `date_range`, `percent_checked`, `show_original` (список значений как текст). Доступный набор зависит от типа целевого свойства; тип результата выводится и хранится.

**Пересчёт.** Изменилось значение `X` у записи `B` → по `property_deps_rev` находим свёртки, которые смотрят на `X`, → по `relation_links` находим записи `A`, которые связаны с `B`, → пересчитываем только их. Изменение самих связей пересчитывает свёртки обеих сторон.

## 3. Формулы

### Язык

Собственный небольшой язык, близкий к формулам Notion по виду, чтобы было привычно. Имена функций английские (как в Notion и Excel); русские синонимы — вопрос заказчику.

```text
prop("Цена") * prop("Количество")
if(prop("Готово"), "✓", format(dateBetween(prop("Срок"), today(), "days")) + " дн.")
round(prop("Часы") / 8, 1)
```

- **Типы:** число, текст, логическое, дата (день или момент), пусто. Списки — только как результат свёртки «показать значения», без функций над списками в первой версии.
- **Операторы:** `+ - * / % ^`, `== != < <= > >=`, `and or not`, `?:` нет — только `if()`. Текст склеивается `+`.
- **Функции (38 и `prop`):** `if ifs empty not` · `abs round ceil floor min max sqrt pow mod sign` · `length lower upper trim contains replace replaceAll slice startsWith endsWith format toNumber join` · `today dateAdd dateSubtract dateBetween formatDate year month day weekday dateStart dateEnd` · `prop`.
- **Ссылки на свойства** в тексте пишутся по имени, а хранятся по ID: переименование свойства не ломает формулу, в редакторе показывается новое имя.

### Реализация — чистый слой без UI

Каталог `Sources/MinervaNoema/Workspace/Domain/Formula/` (входит в подмножество `Domain` из `check-layers.sh`):

| Файл | Что делает |
|---|---|
| `FormulaLexer.swift` | Токены с позициями (для подсветки ошибок) |
| `FormulaParser.swift` | Рекурсивный спуск с приоритетами (Pratt), AST |
| `FormulaTypes.swift` | Вывод и проверка типов на этапе сохранения |
| `FormulaEvaluator.swift` | Интерпретатор AST с лимитами |
| `FormulaFunctions.swift` | Таблица функций: сигнатура, тип результата, реализация |
| `DependencyGraph.swift` | Граф свойств, поиск циклов, топологический порядок |

**Безопасность (FR-13).** Никаких `eval`, `NSExpression`, `JavaScriptCore` и динамического вызова селекторов — только собственный интерпретатор над закрытой таблицей функций. Нет доступа к файлам, сети, другим страницам, кроме значений свойств текущей записи и свёрток. Правило в `check-layers.sh`: запрет `NSExpression|JSContext|NSSelectorFromString` в `Workspace/Domain/Formula`.

**Лимиты:** текст формулы до 4 КБ; вложенность до 64, глубина дерева до 128; не больше 10 000 шагов на одно вычисление; строка результата до 64 КБ; цепочка «формула → свёртка → формула» до 16 уровней. Превышение — явная ошибка ячейки, не зависание.

**Ошибки.** Синтаксические и типовые — при сохранении, с позицией и подсказкой («ожидалось число, получен текст», «нет свойства "Цена"»): формула с ошибкой не сохраняется. Ошибки выполнения (деление на ноль, неверная дата, лимит) пишутся в `calc_error` и показываются в ячейке значком с подсказкой.

**Циклы.** При сохранении формулы или свёртки строится граф с учётом связей (формула → свёртка → формула в другой базе → …). Цикл — отказ сохранить с путём: «Итог → Сумма задач → Оценка → Итог». Во время вычисления — защита глубиной на случай повреждённых данных.

**`today()`.** Значение «сегодня» меняется само, поэтому такие формулы помечаются как зависящие от времени и пересчитываются при открытии пространства и при смене дня. `now()` в первую версию не входит (решение заказчика).

### UI формулы

Окно редактора: поле с подсветкой и автодополнением свойств и функций, справочник функций по-русски, предпросмотр результата на текущей записи и на трёх соседних, ошибка с подчёркиванием места. Тип результата показывается и определяет доступные фильтры.

## 4. Движок пересчёта

`Workspace/Services/Recalculator.swift` (без UI, тестируется отдельно), SQL — в `Persistence/SQLiteWorkspace+Calc.swift`.

1. **Точечная правка** (значение, связь, заголовок): в той же транзакции записи найти затронутые ячейки по `property_deps`/`relation_links`, упорядочить топологически, пересчитать. Если затронуто больше 2000 ячеек — пометить их `calc_dirty` и досчитать фоном пачками.
2. **Изменение определения** (новая формула, смена агрегата, удаление свойства): весь столбец помечается `calc_dirty`, пересчёт фоном пачками по 500 записей в отдельных транзакциях, в шапке столбца — «Пересчёт… 40%». Интерфейс не блокируется, представление видит готовые значения по мере пересчёта.
3. **Открытие пространства:** досчитать все `calc_dirty` (прерванный пересчёт, сбой, `today()`).
4. Запись по-прежнему одна (`DatabaseQueue`), пересчёт идёт через неё же: гонок с правками нет.

## 5. Импорт, экспорт, копии

- **Полный архив** — новые таблицы входят в SQLite-снимок автоматически; AT-12 расширяется сверкой связей и вычисленных значений.
- **CSV-экспорт:** связь — заголовки через «; », свёртка и формула — готовое значение, ошибка — пусто + строка в отчёте.
- **Markdown-экспорт:** связи в карточке свойств как `[[Заголовок]]`.
- **Импорт Notion:** связи восстанавливаются, если CSV содержит ссылки вида `Заголовок (путь.md)` и обе базы есть в архиве — вторым проходом, как ссылки страниц. Формулы и свёртки Notion не переводятся: импортируются как значения (текст/число) с пометкой в отчёте.
- **История версий:** значения свойств в снимки по-прежнему не входят (ограничение 1.0 сохраняется).

## Тесты сверх обычных

- Цикл через две базы и через саму себя; удаление свойства, на которое ссылается формула; удаление связи под свёрткой; запись в корзине внутри связи.
- Деление на ноль, пустые значения во всех функциях, даты на границе перехода на летнее время, `dateBetween` по дням без сдвига пояса (правило FR-10).
- Лимиты: формула 4 КБ, вложенность 64, цепочка 16, 1000 связей в ячейке.
- Прерывание фонового пересчёта (закрытие окна, сбой) → при открытии значения досчитаны.
- Производительность на M1 8 ГБ: правка значения при 20 тыс. записей и свёртке на 1000 связей; полный пересчёт столбца формулы.

## Решения заказчика (10.11.2026)

1. **Связи** двусторонние по умолчанию; при создании есть флажок «без обратной связи». Обратный столбец можно скрыть в представлении.
2. **Имена функций** английские; полная справка по-русски с примерами. Русские синонимы можно добавить позже без поломки старых формул.
3. **Время:** в первой версии только `today()`, без `now()`. Время для сравнений берётся из самого свойства-даты.
4. **Свойства «Создано» и «Изменено»** входят в M9 (этап M9.1). «Изменено» обновляется и при правке текста страницы, и при правке любого её свойства, включая связи. Вычисляемые значения (свёртки, формулы) «Изменено» не трогают — иначе пересчёт менял бы время у сотен записей.
5. **Версия 1.1.0** (решение исполнителя по поручению заказчика): формат архива и данные совместимы, меняется только схема; переход односторонний, откат на 1.0 — из снимка перед миграцией. В заметках к выпуску сказать, что 1.0 не откроет обновлённое пространство.

## Риски

- **Рост записи:** одна правка может тянуть пересчёт многих ячеек — смягчается порогом 2000 и фоновым досчётом.
- **Сложность графа через базы** — циклы проверяются при сохранении, а не только при вычислении.
- **⌘Z в таблице** до сих пор не работает; со связями отсутствие отмены заметнее. Отмена правок таблицы — отдельное решение, не в M9.
- **Встроенное представление** остаётся карточкой из пяти записей: связи и формулы видны, но правка — в полном виде.
