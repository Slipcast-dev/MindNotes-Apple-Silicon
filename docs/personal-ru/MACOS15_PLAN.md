# План: минимум macOS 15 вместо 26

Составлен 13.11.2026. Статус: **шаги 1–5 и 7 сделаны 13.11.2026**, закоммичены (`03be8d1`, `852815a`) и отправлены в GitHub: `hidingSharedBackground()` в `RootView.swift`, `MIN_MACOS=15.0`, `.macOS(.v15)`, проверка `SystemRequirement` в `Updater.stage(image:)` с тестом; `ci.yml` с задачами `tests` (macos-26) и `minimum-macos` (macos-15), `test-notes.sh` с `NOTES_BUILD_ONLY`/`NOTES_BIN`, `scripts/smoke-launch.sh`; документы, ADR-0020, CHANGELOG. CI в GitHub прошёл на обеих задачах. Сборки приложения и Web Clipper имеют `minos 15.0`. Выпуск 1.7.0 — 13.11.2026, по решению заказчика до шага 6: ручная проверка в ВМ с macOS 15 ещё впереди, найденное — в следующих выпусках.

## Цель

Запуск MindNotes и Web Clipper на macOS 15 Sequoia, 26 Tahoe и 27 на Mac с Apple Silicon. Архитектура не меняется: только arm64, Intel не поддерживается (ADR-0009 в этой части остаётся в силе). Сборка по-прежнему на SDK 26 и новее, сейчас SDK 27.2.

Что дальше не входит в план: macOS 13–14 (около 85 мест в коде, включая Observation, EventKit и `onChange`) и сборка для Intel.

## Что показала проверка

`swiftc -typecheck -wmo -continue-building-after-errors -target arm64-apple-macos15.0` по всем `Sources` нашёл ровно три ошибки:

| Файл | Строки | API | Требует |
|---|---|---|---|
| `Sources/MindNotes/Shell/RootView.swift` | 30, 32, 44 | `ToolbarItem.sharedBackgroundVisibility(.hidden)` | macOS 26 |

Установщик Web Clipper (тогда `Plugins/WebClipper/Installer`, теперь — репозиторий `Slipcast-dev/MindNotes-WebClipper`) собирается для macOS 15 без ошибок. Остальные API (прокрутка таймлайна, `Color.mix`, Writing Tools, `@Observable`, `onChange` с двумя параметрами, полный доступ EventKit) есть в macOS 14–15.

## Шаги

### 1. Код: убрать зависимость от macOS 26
- В `Shell/RootView.swift` обернуть `.sharedBackgroundVisibility(.hidden)` в `if #available(macOS 26, *)`. `ToolbarContent` не умеет `if #available` напрямую, поэтому нужна обёртка: свой `ToolbarContent`, который на 26+ применяет модификатор, а ниже возвращает элемент без изменений. На macOS 15 общей подложки нет, так что «ничего не делать» и есть нужное поведение.
- Готово, когда: `-typecheck` с целью macOS 15 проходит без ошибок, а на macOS 27 панель инструментов выглядит как раньше.

### 2. Цель сборки
- `scripts/target.sh`: `MIN_MACOS=15.0`.
- `Package.swift`: `platforms: [.macOS(.v15)]`.
- `LSMinimumSystemVersion` в `build-app.sh` возьмётся из `$MIN_MACOS` сам. У Web Clipper свой минимум — `PLUGIN_MIN_MACOS=15.0` в его `scripts/build.sh` (тогда `scripts/build-webclipper.sh`) (ADR-0019, п. 11, коммит `fdbbd8f`), от `MIN_MACOS` он не зависит. Проверить готовые `Info.plist` приложения, установщика и `.appex`.
- `tests/edition.test.cjs`: при желании добавить проверку, что `MIN_MACOS` и `Package.swift` совпадают.

### 3. Защита от новых API
- Отдельный механизм не нужен: `build-app.sh` в CI собирает весь модуль с `-target $TARGET`, так что API новее 15 без `#available` сломают сборку. `check-layers.sh` проверяет только подмножества слоёв (без `Shell`) и всю защиту не даёт.
- Для ручного поиска всех нарушений сразу использовать `-typecheck -wmo -continue-building-after-errors`. Без этих флагов `swiftc` останавливается на первом файле с ошибкой и прячет остальные.

### 4. Обновления: не ставить несовместимую сборку
Сейчас `Updater.stage(image:)` копирует `MindNotes.app` из образа и не смотрит, какую систему он требует. Если когда-нибудь минимум снова поднимут, пользователь на macOS 15 получит обновление, которое не запустится.
- После монтирования прочитать `LSMinimumSystemVersion` из `Info.plist` в образе и сравнить с `ProcessInfo.processInfo.operatingSystemVersion`. Если система старее, не ставить и сообщить: «Новая версия требует macOS N. Текущая версия продолжит работать».
- Тест в `tests/swift-notes`: сравнение версий (`15.0` против `15.7.1`, `26.0`, `27.2`).
- Этот шаг должен попасть в первый выпуск с минимумом 15. Иначе защита не успеет доехать до пользователей.

### 5. CI
На образе с macOS 15 стоит SDK 15, где нет `sharedBackgroundVisibility`, поэтому **собирать нужно на `macos-26`, а запускать на `macos-15`.**
- Задача `build` (`macos-26`): `./scripts/test.sh`, `./scripts/build-app.sh`, сборка бинарника тестов `notes-tests`. Результаты выгружать артефактом.
- Задача `run-macos15` (`macos-15`, `needs: build`): скачать артефакт, запустить `notes-tests` (в нём есть настоящий `NSTextView`) и проверить запуск приложения (`open -W` с таймаутом или запуск бинарника на несколько секунд без падения).
- Для этого `scripts/test-notes.sh` разделить на «собрать» и «запустить» (например, переменная `NOTES_BUILD_ONLY=1`).
- Перед изменением проверить, что образ `macos-15` в GitHub Actions на arm64 ещё доступен.

### 6. Ручная проверка на macOS 15
Виртуальная машина на Apple Silicon (Tart или UTM, образ macOS 15 IPSW). Компилятор не ловит отличия в поведении и внешнем виде, поэтому вручную:
- Окно и интерфейс: панель инструментов, боковая панель, светлая и тёмная тема, отступы. Интерфейс делался под Liquid Glass, на 15 вид будет проще. Нужно проверить, что ничего не сломалось, а не что вид совпадает.
- Редактор блоков: ввод, выделение, вставка, перетаскивание, Writing Tools (на 15.1+).
- Таймлайн базы: прокрутка, переход к сегодняшнему дню.
- Календарь: первый запрос доступа к Календарю и Напоминаниям, двусторонняя синхронизация.
- Блокировка страниц (LocalAuthentication / Touch ID), уведомления, превью ссылок, ИИ-ассистент.
- Резервная копия: создать на 27, восстановить на 15 и обратно. Схема v10 общая, но проверить обязательно.
- Web Clipper: установка, включение в Safari 18, сохранение страницы.
- Обновление: с 1.6.x на новую сборку на macOS 15; отказ при подсунутом образе с минимумом 26 (шаг 4).

### 7. Документы и выпуск
- Новый ADR-0020 «Минимум macOS 15» вместо раздела о версии в ADR-0009; в ADR-0009 указать, что версия заменена.
- Заменить «macOS 26» на «macOS 15» в README.md, README.ru.md, `docs/en` и `docs/personal-ru` (ARCHITECTURE, BUILD_AND_USE, KNOWN_LIMITATIONS, STATUS, PLAN) и в тексте `scripts/make-dmg.sh`.
- В KNOWN_LIMITATIONS: на macOS 15 нет Liquid Glass; на какой системе проверялось.
- CHANGELOG (en, ru) и запись в TEST_REPORT.md. Выпуск минорный, например 1.7.0.

Риски:

- **Постоянная нагрузка:** любой новый API из SDK 26+ нужно оборачивать в `#available`. Шаг 3 не даст забыть.
